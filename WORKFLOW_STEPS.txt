1. OBJECTIVE & REQUIREMENTS OVERVIEW
================================================================================
The objective of this assignment is to solve the classic NP-hard Traveling
Salesperson Problem (TSP) using a brute-force approach across two implementations:
  1. A pure Python implementation using `itertools.permutations`.
  2. A native C++ implementation using `std::next_permutation`, exposed to Python
     through Cython.
  3. Benchmark both implementations on graphs of sizes N=8, N=10, and N=11 using
     Python's `timeit` module to observe the factorial scaling O((N-1)!) and the
     order-of-magnitude speedup achieved by compiled C++.
  4. Package the resulting library using modern Python packaging standards
     (`pyproject.toml`, `setup.py`, `MANIFEST.in`), build a Source Distribution
     (`sdist`), prepare Git tracking, and provide end-to-end instructions for
     PyPI publication via Twine.

3. STEP 1: PURE PYTHON SOLVER IMPLEMENTATION
================================================================================
- File: `src/python_solver/solver.py`
- Function: `tsp_python(distance_matrix)`
- Logic:
  1. Let N = len(distance_matrix).
  2. Handles edge cases: N <= 1 returns 0; N == 2 returns distance[0][1] + distance[1][0].
  3. For N >= 3, fixes node 0 as the starting and ending origin city.
  4. Permutes the remaining (N-1) cities using `itertools.permutations(range(1, n))`.
  5. Computes route cost: distance[0][p[0]] + sum(distance[p[i]][p[i+1]]) + distance[p[-1]][0].
  6. Tracks and returns the minimum tour cost across all (N-1)! candidate routes.

================================================================================
4. STEP 2: NATIVE C++ SOLVER IMPLEMENTATION
================================================================================
- Header File: `src/cpp/tsp.h`
  Declares the signature:
    `int tsp_solver(const std::vector<int>& dist_matrix, int n);`

- Source File: `src/cpp/tsp.cpp`
  Implementation details:
  1. Takes the flattened 1D distance matrix (size n * n) and node count n.
  2. Cities 1 through n-1 are loaded into `std::vector<int> cities(n - 1)` using `std::iota`.
  3. Uses `const int* matrix = dist_matrix.data();` for pointer dereferencing in the inner loop.
  4. Iterates through all (N-1)! permutations using:
       do {
           // calculate path cost for current permutation
       } while (std::next_permutation(cities.begin(), cities.end()));
  5. Updates `min_cost` whenever a shorter tour is discovered and returns the minimum.

5. STEP 3: CYTHON WRAPPER IMPLEMENTATION
================================================================================
- Cython Definition Header: `src/cython_wrapper/tsp_c.pxd`
  Declares C++ vector and the external function:
    from libcpp.vector cimport vector
    cdef extern from "tsp.h":
        int tsp_solver(const vector[int]& dist_matrix, int n)

- Cython Implementation: `src/cython_wrapper/tsp_wrapper.pyx`
  Function: `tsp_cython(distance_matrix)`
  1. Accepts Python 2D list-of-lists.
  2. Allocates a C++ `std::vector<int> vec_1d` with `reserve(n * n)`.
  3. Flattens the 2D matrix into the 1D vector.
  4. Calls the native `tsp_solver(vec_1d, n)`.
  5. Returns the optimal integer path cost back to Python with minimal overhead.

Benchmark script: `benchmark.py`
Executes on graph sizes N=8, N=10, and N=11 using `timeit.default_timer()`.

Actual Recorded Results:
--------------------------------------------------------------------------------
Graph Size (Nodes) | Routes (N-1)! | Python Time (s) | Cython Time (s) | Speedup
--------------------------------------------------------------------------------
N = 8              | 5,040         | 0.0034s         | 0.00005s        | 71.5x
N = 10             | 362,880       | 0.3384s         | 0.0033s         | 101.7x
N = 11             | 3,628,800     | 3.8315s         | 0.0418s         | 91.6x
--------------------------------------------------------------------------------

Observations:
- Cython C++ is between 71x and 102x faster than Pure Python.
- Evaluating 3,628,800 full routes took only 41.8 milliseconds in Cython C++,
  compared to nearly 4 seconds in pure Python.
- Both implementations returned identical minimum tour costs, confirming mathematical equivalence.
